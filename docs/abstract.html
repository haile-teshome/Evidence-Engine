Abstract Screening

Page abstract · Title and abstract review.

Screens each title/abstract against the criteria using the per-PICO method described in the screening model, at bounded concurrency. Supports single-record and batch calls, reviewer overrides, and an optional relevance re-rank to surface the most likely includes first.

How it works

  1. For each record, the backend builds a prompt from the PICO and the inclusion/exclusion criteria and asks the model for a structured verdict: overall include/exclude/maybe, a reason, and a per-criterion breakdown.
  2. Batch calls (/api/screen/abstract-batch) dispatch records through a bounded thread pool (PARALLEL_SCREENING_WORKERS) and stream progress; the run is cancellable.
  3. Excluded records are bucketed by the criterion that failed, so the PRISMA funnel can report reasons for exclusion. An optional re-rank (/api/papers/rerank) orders the corpus by predicted relevance so likely includes are reviewed first.
  4. A reviewer can override any verdict; the override is stored with is_override = true and carried forward to acquisition and snowballing.

Inputs: deduplicated corpus, PICO, criteria. Outputs: per-paper decisions with reasons and exclusion buckets.

Key endpoints: /api/screen/abstract, /api/screen/abstract-batch, /api/papers/rerank.
