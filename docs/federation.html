Federation model

With no server, reviewer work moves between machines as export/import bundles: the author defines the project and hands out papers, each reviewer screens locally, and their decisions return as a file that merges into the author's store. The author's copy is the source of truth. Invites (POST /api/projects/{pid}/invites, POST /api/invites/{token}/accept) model membership; a ?invite=TOKEN URL routes the app to the accept banner.

Implementation status. The collaboration data model, assignment, tagging, calibration, decisions, conflicts, adjudication, and risk-of-bias are built and tested. The bundle export/import that physically moves work between separate machines is the remaining piece to implement. Its format must be versioned (a version field plus a schema) before collaborators depend on it, so later changes do not break existing bundles.
